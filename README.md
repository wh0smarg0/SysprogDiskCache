# SysprogDiskCache

**Дискретно-подієвий симулятор роботи операційної системи** з буферним кешуванням дискових секторів і плануванням операцій введення-виведення.

**Курсова робота** з дисципліни «Системне програмування». **Варіант 2.**

## Мета проєкту

Моделювання взаємодії процесів, центрального процесора, буферного кешу та жорсткого диска для дослідження алгоритмів керування кешем і планування дискових запитів. Програма використовує віртуальний час і не виконує реальних операцій із диском.

## Реалізовані можливості

- **Round Robin** — розподіл процесорного часу між процесами.
- **Трьохсегментний LFU-кеш** — лівий, середній і правий сегменти; облік звернень та витіснення буферів.
- **FIFO, LOOK, FLOOK** — алгоритми планування дискових операцій.
- **Cache Hit / Cache Miss** — обробка повторних звернень і завантаження секторів.
- **Write-back / FLUSH** — відкладений запис змінених буферів і фінальне скидання.
- **Coalescing** — об’єднання запитів до одного сектора.
- **BUFFER WAIT / WRITE WAIT** — моделювання очікування доступного буфера або завершення запису.
- **IRQ** — обробка завершення дискових операцій та розблокування процесів.
- **Журнал подій і CSV-статистика** — хронологічні повідомлення в консолі та результати сценаріїв у `summary.csv`.

## Вимоги

- Python 3 (рекомендовано **Python 3.10+**).
- Сторонні Python-бібліотеки не потрібні — використовується стандартна бібліотека.

## Запуск

1. Клонуйте репозиторій або завантажте його як ZIP.
2. Відкрийте термінал у кореневій папці проєкту, де розташовано `main.py`.
3. Виконайте:

   ```bash
   python main.py
   ```

   У Windows, якщо команда `python` недоступна, спробуйте:

   ```powershell
   py main.py
   ```

Після запуску програма виконає **13 основних тестових сценаріїв**, виведе журнал подій, збереже підсумкову таблицю у `summary.csv`, а потім виконає окремий контрольований **тест №14 — WRITE WAIT**.

У разі успішного проходження останнього тесту в консолі з’явиться:

```text
TEST PASSED: WRITE WAIT
```

## Структура проєкту

```text
SysprogDiskCache/
├── main.py                  # Запуск сценаріїв і формування summary.csv
├── core/
│   ├── process.py           # Модель процесу
│   ├── kernel.py            # Часові параметри системних подій
│   └── simulator.py         # Основний цикл моделювання
├── hardware/
│   └── hard_disk.py         # Модель жорсткого диска
├── memory/
│   └── buffer_cache.py      # Трьохсегментний LFU-кеш
├── scheduling/
│   └── io_scheduler.py      # FIFO, LOOK і FLOOK
├── utils/
│   └── logger.py            # Журналювання подій
└── summary.csv              # Підсумкові результати сценаріїв
```

## Тестові сценарії

У `main.py` визначено такі перевірки:

| № | Сценарій |
|---:|---|
| 1 | Просте читання |
| 2 | Модифікація сектора |
| 3 | Читання та запис |
| 4 | Дедуплікація запитів |
| 5 | Витіснення зміненого буфера (Write-back) |
| 6 | LOOK: читання та запис |
| 7–8 | LOOK із різними обмеженнями послідовних звернень |
| 9 | FLOOK за умов повільного CPU |
| 10 | Переповнення кешу |
| 11 | Повторне читання (Cache Hit) |
| 12 | Перевірка витіснення LFU |
| 13 | Конкурентний Write-back |
| 14 | Окремий контрольований тест WRITE WAIT |

> **Примітка:** сценарії 1–13 потрапляють до `summary.csv`; тест 14 виконується окремо й не додається до CSV.

## Формат результатів

Файл `summary.csv` містить такі колонки:

| Колонка | Опис |
|---|---|
| `Сценарій` | Назва тесту |
| `Алгоритм` | FIFO, LOOK або FLOOK |
| `Час (мс)` | Тривалість моделювання |
| `Hits` | Кількість попадань у кеш |
| `Misses` | Кількість промахів кешу |
| `Coalesced` | Кількість об’єднаних запитів |
| `Читань` | Кількість фізичних операцій читання у моделі |
| `Записів` | Кількість фізичних операцій запису у моделі |

> **Важливо:** сценарії задані безпосередньо в `main.py`. Завантаження тестів із зовнішніх JSON-файлів у цій версії не передбачене.
