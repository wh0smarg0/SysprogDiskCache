# SysprogDiskCache

**Дискретно-подієвий симулятор роботи операційної системи** з буферним кешуванням дискових секторів, процесорним плануванням, обробкою апаратних переривань і плануванням операцій введення-виведення.

**Курсова робота** з дисципліни «Системне програмування». **Варіант 2.**

## Мета проєкту

Моделювання взаємодії процесів, центрального процесора, буферного кешу та жорсткого диска для дослідження алгоритмів керування кешем, планування дискових запитів і механізмів синхронізації.

Програма використовує віртуальний час і не виконує реальних операцій із диском. Моделювання реалізовано за дискретно-подієвим принципом: система переходить до найближчої значущої події, враховуючи залишок виконання поточної процесорної операції, залишок процесорного кванта та момент завершення активної дискової операції.

## Реалізовані можливості

- **Round Robin** — розподіл процесорного часу між процесами з урахуванням тривалості системних викликів та обробки переривань.
- **Трьохсегментний LFU-кеш** — лівий, середній і правий сегменти; облік частоти звернень та витіснення буферів.
- **FIFO, LOOK, FLOOK** — алгоритми планування дискових операцій.
- **Cache Hit / Cache Miss** — обробка повторних звернень і завантаження секторів із диска.
- **Write-back / FLUSH** — відкладений запис змінених буферів і фінальне скидання.
- **Coalescing** — об’єднання однакових запитів до одного сектора.
- **BUFFER WAIT / WRITE WAIT** — моделювання очікування доступного буфера або завершення запису.
- **Асинхронне дискове введення-виведення (DMA)** — виконання дискових операцій без блокування процесора на весь час їхнього виконання.
- **Апаратні переривання (IRQ)** — обробка завершення дискових операцій, оновлення стану кешу та розблокування процесів.
- **Переривання системних викликів** — можливість надходження IRQ під час виконання процесу в режимі ядра (`SYSCALL`).
- **Переривання користувацьких обчислень** — можливість надходження IRQ під час виконання користувацького коду (`AFTER_READ`).
- **Збереження стану перерваної операції** — після обробки IRQ зберігається залишок часу виконання поточної фази, а тривалість обробника переривання враховується у процесорному кванті.
- **Журнал подій і CSV-статистика** — хронологічні повідомлення в консолі та результати основних сценаріїв у `summary.csv`.

## Вимоги

- Python 3 (рекомендовано **Python 3.10+**).
- Сторонні Python-бібліотеки не потрібні — використовується стандартна бібліотека.

## Запуск

1. Клонуйте репозиторій або завантажте його як ZIP.
2. Відкрийте термінал у кореневій папці проєкту, де розташовано `main.py`.
3. Виконайте:

   ```bash
   python main.py
   ```

   У Windows, якщо команда `python` недоступна, спробуйте:

   ```powershell
   py main.py
   ```

Після запуску програма:

1. Виконає **13 основних тестових сценаріїв**.
2. Виведе хронологічний журнал системних подій.
3. Збереже підсумкову статистику основних сценаріїв у `summary.csv`.
4. Виконає **три додаткові контрольовані тести №14–16**:
   - №14 — перевірка механізму `WRITE WAIT`;
   - №15 — перевірка IRQ під час системного виклику (`SYSCALL`);
   - №16 — перевірка IRQ під час користувацьких обчислень (`AFTER_READ`).

Контрольовані тести перевіряють правильність поведінки симулятора за допомогою програмних перевірок (`assert`).

## Особливості моделювання апаратних переривань

У симуляторі реалізовано можливість переривання поточної процесорної операції під час завершення дискового введення-виведення.

Тривалість наступного інтервалу моделювання визначається за формулою:

Δt = min(Tstage, Tquantum, Tio),

де:

- `Tstage` — залишок часу виконання поточної фази;
- `Tquantum` — залишок процесорного кванта;
- `Tio` — час до завершення активної дискової операції.

Якщо дискова операція відсутня, третій аргумент не враховується.

Під час надходження IRQ:

1. Виконання поточної процесорної операції призупиняється.
2. Фіксується стан перерваної фази (`SYSCALL` або `AFTER_READ`).
3. Виконується обробник переривання тривалістю **0,05 мс**.
4. Час обробника списується із залишку процесорного кванта перерваного процесу.
5. Залишок виконання поточної операції зберігається.
6. Після завершення обробника процес може продовжити виконання або повернутися до планування Round Robin, якщо його квант вичерпано.

У журналі подій відповідний механізм відображається повідомленнями:

```text
CPU INTERRUPTED
IRQ BEGIN
IRQ END
CPU RESUME
```

Це дозволяє перевіряти коректність обробки апаратних переривань як у режимі користувача, так і під час виконання системних викликів у режимі ядра.

## Особливості реалізації

- Симулятор використовує віртуальний час і не взаємодіє з реальним дисковим обладнанням.
- Дискові операції виконуються асинхронно відносно процесорних обчислень.
- Системні виклики не є неподільними операціями та можуть бути перервані IRQ.
- Обробка апаратних переривань враховується в загальному часі моделювання та процесорному кванті.
- Тривалості системних викликів і обробки IRQ задаються параметрами моделі.
- Сценарії тестування визначені безпосередньо у `main.py`.
- Завантаження тестів із зовнішніх JSON-файлів у поточній версії не передбачене.
